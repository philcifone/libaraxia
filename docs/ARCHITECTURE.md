# Architecture reference

The detailed map of Libaraxia: every blueprint, utility module, table, template convention and script. Moved out of `CLAUDE.md` on 2026-11-11 so it isn't loaded into every session; `CLAUDE.md` keeps the rules (gotchas, access model, security conventions) and points here. Read the section you need, and keep it in step when you add or rename a module.

## Application Structure
- **app.py**: application factory `create_app()`. Loads `.env`, picks the config, sets up CSRF, Flask-Limiter, Flask-Mail and Flask-Login, adds security headers, optional ProxyFix, and registers the blueprints. `/` redirects to registration when there are no users, otherwise to `/base/`.
- **config.py**: `DevelopmentConfig` / `ProductionConfig` / `TestingConfig`, chosen by `FLASK_ENV` (cookies, mail, email verification).
- **manage.py**: database CLI: `migrate`, `status`, `backup` (see Database Management).
- **models.py**: `User` (Flask-Login), `admin_required`, username rules (`is_valid_username`; `username_error(conn, name, user_id=None)` for every way a name is chosen: the rules, `username_shadows_route` (a name that a fixed route next to a `<username>` route would swallow, read from the live URL map), and taken ignoring case), and friendship/library helpers (`is_friends_with`, `get_friendship_status`, `get_library_members`, `shares_library_with`, `circle_ids`, `can_view_book`).

## Blueprints (`/blueprints/`, URL prefix in brackets)
- **auth** (`/auth`): register, login (with remember-me), logout, email verification and resend. Registration can be closed with `ALLOW_REGISTRATION=False`.
- **base** (`/base`): main library view at `/base/index` with search/sort/filter and infinite scroll; shared (household) library; friends' libraries.
- **books** (`/books`): add, edit, `/books/thumbnail` (search-result cover proxy), remove from library / restore (deaccession), delete for mistakes (POST), detail page, ISBN/title lookup, cover fetching, ownership transfer within a household.
- **collections** (`/collections`): statuses (per type, `media.STATUSES`) and custom shelves, on Books / Movies / Music tabs (`?type=`, ROADMAP 8C). Custom shelves (`user_collections.media_type`, migration 027) belong to one section; the item page offers its section's shelves. Shelf cards everywhere (Collections, profile shelves and wishlist rows) are `_shelf_rows.html`, fed by `utils/shelves.py`. The Books tab's Goodreads shelves card (14c) posts to `/collections/goodreads_shelf` (mode `new` or `add`), which runs bulk's `shelf_add` plan + apply so the collection page's banner can undo it; Open in Books links the grid with `?gr_shelf=<name>&show=all`.
- **user** (`/user`): profiles (tabs Overview / Stats / Reviews for you and your friends), **Settings** (`/user/settings`, `user.settings`, the sidebar gear, 14c: tabs Library and Account for everyone, Admin for admins via `admin.settings_context`; templates `settings.html`, `_settings_library.html`, `_settings_account.html`, `_admin_settings.html`), inline settings (email/username/bio/password/avatar), library CSV export (Section column: Yours, Shared (<owner>) for the household's shelf, Your data on others' items; Lent To / Lent On / Due Back at the end for the first two, 16.0d; `utils/export.py`; the data ZIP has `loans.csv`) and "export my data" ZIP, personal library backups (`/user/backups/...`, `utils/personal_backups.py`), Settings → Account (deactivate/delete own account), **Goodreads CSV import** (every user: upload page, `/import_goodreads/plan` → `/review` → `/choose` → `/apply`, `/discard`; logic in `utils/goodreads_plan.py`, parser in `utils/goodreads.py`; undo is the bulk route), household invite/accept/decline/remove/leave (logic in `utils/households.py`).
- **read** (`/read`): ratings/reviews and reading sessions (dates started/completed).
- **tags** (`/tags`): per-user tags.
- **admin** (`/admin`): the Admin tab of Settings (`settings_context`; `/admin/settings` now redirects to `/user/settings#admin`, 14c), site backups (`/admin/backups`: back up, restore, download the database, delete; `utils/backups.py`), user management (deactivate/delete dialog), avatar management, orphaned image cleanup, unowned books (reassign), bulk cover fetch, household (library) membership.
- **feed** (`/feed`): activity feed of friends' reviews/updates, likes, dismissals.
- **wishlist** (`/wishlist`): your wishlist (`/view`: books, movies and music, with Books / Movies / Music / All tabs, `?show=`; sections from `_wishlist_sections`, shared with a friend's `/user/<username>`), adding (`/add?type=book|video`: the shared `add_item.html` with a note field), moving items onto the shelf (Library or Movies), friends' wishlists.
- **friends** (`/friends`): friend requests, friend list, notifications page, user search API.
- **videos** (`/videos`) and **records** (`/records`): the Movies & TV and Music sections (Phase 8; Music was "Vinyls" until 2026-11-08: vinyl, CDs and cassettes, one item is an "album", while code, URLs and the DB say "record"), both built by `blueprints/media_section.py` (a `Section` per type, `make_blueprint`; endpoints `videos.show_video`, `records.add_record`, ... via `media.item_endpoint`). Own / household (`/shared`) / friends' grids (`media_grid.html`; search and filters in the row under the tabs, `_search_sort_filter.html`), add (`add_item.html`, shared with Add Book; Movies & TV's add button has a TV show entry, `?kind=tv` via `Section.kind_arg`), edit (`media_form.html`), detail (`book_detail.html` worded by `m`). Movies: TMDb title search `/videos/search`, barcode lookup `/videos/lookup`, scanner. Music: the Search tab lists albums (`/records/albums`: Discogs masters or MusicBrainz release groups, 16.0), then an album's pressings (`/records/pressings`), or "Use this" on an album fills the form from its main pressing (`/records/lookup?discogs_master=` / `?mb_group=`); `?format=` keeps vinyl, CD or cassette. When nothing matches as an album, `/records/search` lists pressings (also used by Do I Have This? and the cover finder). Discogs first when `DISCOGS_TOKEN` is set (`utils/discogs_lookup.py`), else or when busy MusicBrainz (`utils/music_lookup.py`); a later page never switches source. `/records/lookup?discogs=`, `?mbid=` or `?barcode=` (barcodes and the scanner since 8B.12); reads `library_records`. For Movies: detail (`book_detail.html` with video wording; `/books/book/<id>` redirects videos here), barcode duplicate check. Reads the `library_videos` view. **The UI calls the section "Movies & TV"** (15.1; "Movies" before; sidebar, headings, flashes, feed, the Books | Movies & TV | Music switch, which fits at phone width in all four styles) and shows the VHS format as **"Cartridge"** (`media.format_label`, the `format_label` template filter; a novel reference, Phil's choice). Code, URLs and the DB keep "video" and `format = 'VHS'`; a DVD is a video row with `format = 'DVD'`. Wording per type comes from `media.media_labels()`: a video without a kind gets the section's words ("movie or show", "movies and shows"), `media_labels('video', kind)` a kind's (`media.KIND_WORDS`: "TV Show", "Creator", "created by"). Pages about one item use `media.item_labels(row)` (templates: `labels_for(row)`, `Section.item_m(values)` on the forms and flashes), so a query feeding one should select `video_kind`; without it the row reads as a movie. `SECTION_WORDS` is the section name in running text ("movies and TV").
- **reviews** (`/reviews`, ROADMAP 13): the sidebar's Reviews. `/reviews/?type=` has three rows per type (your reviews, friends' reviews, finished not reviewed yet; `_shelf_rows.html` with stars), `/reviews/all/<mine|friends|unreviewed>` the "See all" cards (`?by=<friend>`), `/reviews/find?type=&q=` the floating [+ Review] search (your view rows and your household's, never others'). Writes nothing: every link goes to `read.rate_review` with `?from=reviews` (crumb and save go back to Reviews). "Add it as not owned" opens the type's add page with `?not_owned=1&then=review&title=`, and saving lands on the review page. Queries in `utils/reviews.py`.
- **have** (`/have`): Do I have this? (ROADMAP 8E): scan or type a barcode, ISBN or title; answers own / household / wishlist / not owned / removed / not here with your status and rating. Matching and scope in `utils/have.py`; `static/have.js` reloads the page with `?q=<code>`. On "Not here" (13b) `have.js` asks `/have/online?q=` (60/hour per user; re-checks locally and calls out only on a miss): `utils/have_online.py` asks Google Books / Open Library, TMDb (UPCitemdb for a barcode) and Discogs (MusicBrainz backup) in parallel with one 5 s deadline, ranks the candidates (`score_text`: word coverage, exact-title and creator bonuses) and gives each add links carrying its id. The add pages look `?tmdb_id=`, `?discogs=`, `?mbid=` up on load (`Section.lookup_url` -> `data-lookup-url`), `?isbn=` / `?barcode=` as before, and take `?title=` / `?author=` (`media.add_prefill`). `/have/local?q=<code>` (14c) is the same local check as JSON, codes only: `add_item.js` runs it on a scanned or typed code before the online lookup and shows the matches in the duplicate notice (`have.verdict_label` words them for both). Loans (16.0d): a `borrowed` verdict for someone else's copy lent to you, and "lent to bob since Mar 2026" on your and your household's copies (`find` drops the loan from anyone else's).
- **covers** (`/covers`): background "fetch missing covers" jobs: start (scope `own`, or `all` for admins), status, stop, dismiss. Started from the Goodreads import result, Settings → Library and admin → placeholder covers. Also the cover crop tool's two POST routes (ROADMAP 15.3): `/covers/crop/source` stages a picked photo, `/covers/crop/preview` renders geometry to a JPEG (nothing stored), and `/covers/crop/save/<book_id>` (16.0a) applies the crop to an existing item's cover there and then (owner or admin; the source must be its own cover, a staged photo or the fetched cover the form holds), which is what Save does on an Edit page.
- **photos** (`/photos`, ROADMAP 16.0a): photos beyond the cover, owner or admin (404 for anyone who can't see the item, 403 for someone who can but doesn't own it). `POST /photos/<book_id>/<kind>` adds one of the single kinds (`photos.kinds_for`: back, spine (left), side (right), top and bottom, every type since 16.0c; replacing deletes the old file) or gallery photos (field `photo`, several at once); `POST /photos/photo/<id>/delete`, `/caption` and `/crop` (JSON `{geometry}` from the cover's crop tool in photo mode, `cover_crop.js` `cropPhoto`; renders from the photo's own file, saves a new one, removes the old). JSON to fetch, a redirect to the edit page's `#photos` for a plain form. The edit page's Photos card is `_photos_edit.html` (+ `static/photos.js`: uploads one file at a time with a progress line); the item page's "More photos" gallery is a dialog in `book_detail.html` (+ `book_detail.js`).
- **The 3D item** (Shelf style only, 16.0a): `utils/item3d.py` decides an item's shape (`shape_for`: book; sleeve for vinyl; jewel for a CD; case for a DVD or cassette; tape for a VHS), which photos it needs (`NEEDS`, `missing`) and builds the `model` (face URLs, `aspect` and `depth` read from the photos' own sizes), or None until every needed photo is there: no drawn faces (a CD with only a front and back is a paper sleeve, `paper`: thin, card edges). `templates/_item3d.html` `item3d_box(model)` draws the six CSS 3D faces (styles.css "The 3D item"); a face without a photo shows a placeholder (`model(..., placeholders)`, from `faces.placeholder_urls`) or is drawn plain. On the item page the cover button's `openCover` (book_detail.js) opens `#item-3d` when it's on the page and the style is shelf, else the gallery from the cover (when there are more photos), else `#cover-zoom`; the box is turned by pointer drag with momentum, keys and Front / Spine (Left, Right for a VHS) / Back, and `faceLight` shades each face. The same macro, still, upright and spines out, half each side of the title, puts up to `HEADING_BOOKS` of your own 3D books on the Shelves heading (`item3d.heading_books`, from `base.index` through `shelf_header(heading_books=)` to `page_heading(books=)`; chosen by `session['heading_seed']`, drawn at login), and your VHS tapes on the Movies one (16.0c: `heading_books(..., media.VIDEO)` from the section's `index` in `media_section.py`).
- **faces** (`/faces`, ROADMAP 16.0c, `docs/FACES-SPEC.md`): placeholder faces. Admins: `GET /faces/admin` (Admin -> Placeholders, linked from Settings' Maintenance; `templates/admin/faces.html`, one tab per medium, `#medium-<medium>`), `POST /faces/admin/add` (medium, kind, name, image; saved under `static/uploads/faces/`, a top or bottom turned to lie wide and a spine or side to stand tall), `/<id>/rename`, `/<id>/delete`, `/<id>/crop` (the crop tool in photo mode, `data-return` brings it back to the medium's tab), `/sets/add`, `/sets/<id>/update` (name, `face_<kind>` members), `/sets/<id>/delete`. An item's owner or admin (photos' rule): `POST /faces/item/<book_id>/choose` (kind, placeholder_id; empty for the default) and `/faces/item/<book_id>/set` (set_id), both back to the edit page's `#photos`. The add forms' `face_set` applies a set to the new item (`faces.apply_on_add`; the `face_sets_for(media_type)` template global lists them).
- **values** (`/values`, ROADMAP 16.0a): `POST /values/fetch/<book_id>` (the edit page's Fetch value, `static/value_fetch.js`: answers only; the form stores it), `POST /values/start` (the bulk Fetch values job from Settings, Library; a `cover_jobs` row of kind `value`), `POST /values/test` (admins: Test value sources in Maintenance).
- **loans** (`/loans`, ROADMAP 16.0d, `docs/LENDING-SPEC.md`): `POST /loans/<book_id>/lend` (form `borrower` = a user id or `other` with `borrower_name`, `lent_at`, `due_at`, `note`), `POST /loans/<loan_id>/return` (`returned_at`), `POST /loans/<loan_id>/delete`; each commits and comes back to the item page's `#loans` with a flash (a `LoanError` is the flash). 404 for anyone who can't see the item. The item page's Loans section (`book_detail.html` `#loans`: the open loan's banner, Mark returned, the Lend panel with its name field shown by CSS for Someone else, the history in a `<details>`) is fed by `books.render_item_page` (`loan_manage`, `loan_history`, `open_loan`). `models.can_view_book` lets a borrower see what they borrowed. The Notifications page links a notification to its item (`related_book_id`). `GET /loans/borrowed` (`loans_borrowed.html`) lists what you have borrowed, opened from your profile's Borrowed row (`shelves.borrowed_shelf`, own profile only). The grids' Lent badge (top centre; in Shelf a tag under the item like the others) comes from the `lent_map(rows)` template global and `card_json`'s `lent_to` (its `looker_id` is who is looking, not whose marks), both limited to the viewer's household's shelf; Show: Lent out is `shelf_filter`'s `lent` (`lent_ok=False` on a friend's grid, where the panel doesn't offer it); Collections adds a Lent out row per tab (`shelves.lent_shelf`).
- **bulk** (`/bulk`, ROADMAP 14a): bulk edit, the routes over `utils/bulk.py`. `POST /plan` (writes nothing; `{action, params, ids}` or a view selection `{view, args}`, resolved here and returned as the plan's `ids`), `POST /apply` (409 with the fresh plan when the fingerprint is stale), `POST /<id>/undo` (`{banner: false}` from Profile), `POST /selection` (the sheet's list of what each selected item has now), `GET /genres`, `GET /options`. Rate-limited per user. The result banner comes from `session['bulk_result']` via `pop_bulk_result()`.

## Utilities (`/utils/`)
- **database.py**: `get_db()` (request-scoped connection, closed at teardown), `get_db_connection()` (a new connection: `sqlite3.Row`, `PRAGMA foreign_keys = ON`), `database_path()`.
- **book_utils.py**: Google Books / Open Library lookups (the Goodreads-scraping BookCover API was dropped 2026-11-08: slow, often timed out), ISBN helpers, cover search and download (`save_best_cover`: tries candidates in order, keeps the largest real cover, through an SSRF guard that only fetches public hosts; `google_cover_candidates` turns a Google link into its 800x1200 and 128 px versions, ROADMAP 8F), `process_image` for uploads, `get_filter_options`.
- **cover_crop.py**: the cover crop / perspective tool's server side (ROADMAP 15.3): `parse_geometry` (the JSON the browser sends: fractions of the image, never pixels), `render` (optional `flip_h` / `flip_v` mirror the source, then the quarter turn, then a rect crop or a perspective warp, then for `mask: "disc"` a CD / DVD cut-out with a see-through spindle hole, RGBA, saved as WebP through `image_utils.ALPHA_FORMAT` / `save_alpha` while every other cover stays JPEG whose coefficients `perspective_coeffs` solves in pure Python), staged uploads (`stage_upload`, `is_staged`, `sweep_staged`) and `apply_form_crop` / `crop_or_flash` for the four add/edit routes plus the wishlist's add (priority: valid crop > upload > fetched cover > existing). Only staged files are deleted because the browser named them.
- **image_utils.py**: `is_safe_upload_path`, `delete_image_file` (refuses paths outside `static/uploads/`), and orphaned image detection/cleanup.
- **goodreads.py**: the Goodreads CSV's parser (`decode_csv`, `parse_row`: cleaned fields plus the Book Id and every shelf) and the plain writers the import uses (`create_book`, `set_status`, `add_sessions`, `add_wishlist`). `custom_shelves` / `shelf_book_ids` (14c) read the custom shelves (not read / currently-reading / to-read / DNF) back out of `goodreads_rows.shelves` for the Collections page's Goodreads shelves card.
- **goodreads_plan.py**: the granular Goodreads import (ROADMAP 14b, `docs/GOODREADS-IMPORT-SPEC.md`). No Flask. `stage` (upload into `goodreads_staging`, one per user, swept after 24 h) → `plan` (every row matched with `BookIndex` or the Book Id memory of earlier imports, sorted into `BOXES` with a default choice, `adds` and `reason`; a `fingerprint` over the staged rows and the user's data) → `choose` (per-row choices, NULL = the box's default) → `apply` (checks the fingerprint, raises `StalePlan`; one SAVEPOINT per row; journals every touched book in `bulk_edits` action `goodreads` so the bulk undo route reverts it, with `after_undo` deleting books it created when nobody else has data on them; records `goodreads_imports` and `goodreads_rows`). `provenance(conn, user_id, book_id)` is the book page note. A personal backup is taken first (`blueprints/user.py`).
- **photos.py** (16.0a): item photo queries (`photos_of`, `slides`, `add`, `delete`, `label` (a book's pages are "Fore-edge", "Top edge", "Bottom edge"), and `box_faces`: a page of items' top and right side faces (photo, else placeholder; a VHS's or a CD's right side falls back on its spine; with neither, a book's face is lined pages, styles.css "book pages") for the Shelf style's flat cover box, the `box_faces` template global, used by the item page, `_book_grid.html` and `card_json`); `MAX_PER_ITEM` 30. Files are written by `image_utils.save_photo` (upright, at most 2000 px, re-encoded with no metadata, so no GPS) under `static/uploads/photos/<book_id>/`, removed through `delete_image_file`; deleting an item removes its folder (`delete_photo_folder`), and `find_orphaned_images` counts `item_photos.path` as in use.
- **faces.py** (16.0c): placeholder faces. `MEDIA` (book, vinyl, cd, cassette, dvd, vhs; checked in code), `medium_for`, the library (`library`, `add_placeholder`, `rename_placeholder`, `replace_image`, `delete_placeholder`), sets (`create_set`, `update_set`, `delete_set`), an item's choices (`options_for`, `chosen`, `choose`, `apply_set`, `sets_for_type`, `apply_on_add`) and `placeholder_urls` (which placeholder each face shows: the owner's pick only, nothing automatic; a photo wins, and a VHS sleeve's right side is its left side's photo).
- **condition.py** (16.0a): the condition grades per type (records: Goldmine with Discogs' labels, record and sleeve; books: the booksellers' scale; movies: used-media terms), `clean` validates a code for a type. Kept in step with the `condition_grades` table by a test.
- **money.py** (16.0a): whole cents in, `parse` ('12.50' -> 1250), `plain`, `show` (the `money` template filter); `currency()` is `VALUE_CURRENCY`.
- **copy_fields.py** (16.0a): the add/edit forms' "This copy" fields (`_copy_fields.html`, in `_item_fields.html` except on the wishlist's add): condition, price paid, value and where it came from (`manual`, `discogs`, `ebay`), a record's Discogs release. `from_form` / `save` for every add and edit route; an unchanged value keeps its source, a typed one is manual.
- **catalog_card.py** (paper-cards trial, Shelf only): the item page's catalog card (`_catalog_card.html`, which stands in for the facts badge in Shelf): `entry(book)` gives the call number (a Dewey class from the Google Books genre via `CLASSES`, or the format for movies and music; a Cutter-style mark; the work mark; the year), the AACR2 heading, title paragraph, physical description, standard number, tracings and the accession number (the row id). Also `stamp_date` (the `|stamp_date` filter, "NOV 13 2026"), the date stamps on the Friends card and the item page's book card.
- **valuation.py** (16.0a): `fetch(row)` -> `Result` (never raises): Discogs price suggestions for a record at its grade (matched by barcode or catalogue number when it has no release id), the eBay Browse API's median asking price for a book's ISBN or a movie's barcode (at least 3 listings; app token cached in memory). Only `VALUE_CURRENCY` is accepted. `source_for(row)` says whether Fetch value shows; `test_sources()` is Maintenance's check.
- **cover_jobs.py**: the background cover fetcher, and since 16.0a the value fetcher (`kind = 'value'`, migration 039: `media_types`, `skip_days`; `value_scope_sql`; one item every 2 s, a busy source waited out; never over a `manual` value). A `cover_jobs` row (migration 022) is the job and its progress; a daemon thread per process works through it one book at a time (`book_utils.fetch_cover_for_book`). `worker` + `heartbeat_at` let another gunicorn worker take over a job whose process died; the next `/covers/status` poll restarts it. Tests never start the thread: they call `run_pending()`.
- **media_covers.py**: the cover fetcher's lookup per type: books by ISBN; movies by barcode (UPCitemdb) or TMDb by title; albums by barcode or artist + title (Discogs, MusicBrainz). Keeps a title match only when `same_title` (and for albums `same_artist`) hold. `book_utils.missing_cover_sql` says which items qualify (a dead link counts as missing, `image_utils.cover_missing`).
- **search.py**: the grid search boxes' matching (ROADMAP 7.2b): `fold()` (an SQL function on every connection, registered in `get_db_connection`) and `match(term, columns, viewer_id)`: every word, accent- and punctuation-free, in any column or the viewer's tags.
- **reviews.py**: the Reviews section's lists (`reviews_by`, `unreviewed`, `list_rows`, `shelves`), the [+ Review] search (`find`) and the add pages' `then_review_values`. "Newest first" = latest finished date, then rowid (read_data has no timestamp). Also feeds the profile's recent reviews.
- **stats.py**: the profile's statistics (ROADMAP 12.1): `type_stats(conn, user_id, kind)`, the same numbers for books, movies and music (videos also `by_kind`, owned and watched per movie / TV, shown as one line when there's any TV; hours stay one number, 15.1) (owned vs finished, pages or hours, chart `by_month`, genres, creators, ratings, decades), drawn by `_profile_stats.html`.
- **sorting.py**: the grids' sort orders (ROADMAP 11.4): `choice(args, type)` and `order_by(sort_by, order, viewer_id)` (nulls last, title/id tiebreak; date read and rating are the viewer's). The sort menu `_view_bar.html` is built from `BY_TYPE`.
- **grid_query.py**: the ids a grid shows (ROADMAP 14a): `books_query` (the Books grid's WHERE, used by `base.library_page`), `term_match` (the search box's condition, shared with the grid's search hints) and `view_ids(conn, user, view, args)` for the whitelisted views in `VIEWS` (`book|video|record:mine|household`). Every grid searches itself (16.0): the search box submits to the page it's on and keeps the filters, sort, view and members; the old `/books/search` redirects its query string to the Household grid (your own when you share with nobody). Movies and Music go through `Section.filtered` (Movies & TV's `?kind=movie|tv` too, 15.1; offered once the shelf has both kinds, `get_filter_options` `kinds`). Change a grid's filters here, or bulk edit's "select all in this view" stops matching the page. `from_goodreads` also takes `?gr_shelf=` (one Goodreads shelf, 14c).
- **bulk.py**: bulk edit (ROADMAP 14a, `docs/BULK-EDIT-SPEC.md`). No Flask: `plan` / `apply` / `undo` / `history` / `recent` / `selection` / `genres` / `options`, and `ACTIONS`, the whitelist (genre, format, kind (Movie or TV, videos only, offered on the Movies & TV grids; 15.1), owned, remove, restore, faces (a placeholder set fills the items' `item_faces`, skipping items of another medium; offered under More where `face_sets_for` has sets; 16.0c): owner or admin; status, shelf_add/shelf_remove (custom collections; the UI says "collection"), tag_add/tag_remove: anything `can_view_book` allows). Every write repeats the plan's before-value and the permission in its WHERE; one SAVEPOINT per item with its journal row; a SHA-256 fingerprint of the plan makes a stale apply a 409. Undo writes back only items still as the edit left them. Journals last 30 days (swept on apply); 500 items per edit.
- **media.py**: books, videos and records (Phase 8): media types, formats per type (`shown_format(row)`, the `item_format` filter: none for an unshelved movie or album, whose stored format is kept), views and endpoints per type (`VIEWS`, `item_endpoint`; templates get `item_url(row)` and `labels_for(row)`), statuses per type, video kinds (`VIDEO_KINDS`, `video_kind()` turns a form value into what's stored, `kind_of(row)` reads NULL as movie; ROADMAP 15.1), wording per type (`media_labels()`, passed to templates as `m`), barcode helpers (`classify_code`, `normalize_barcode`, the server twin of `scanner.js`) and `only(type, column)` for queries on `read_data`/`collections`/`reading_sessions`.
- **search.py** (online part, 16.0): the Add pages' Search tab. `split_by` reads "X by Y" as title and creator (books and music), `by_or_plain` runs that, keeping only rows that `fits` (whole words, folded), else the words as typed; `next_page` builds each answer's `next` (the query parameters for "Show more": `page`, `by`, `src`, `level`), which `add_item.js` appends to the same URL. Books 10 a page (`book_utils.search_books_page`, Google then Open Library), movies 10 (`media_lookup.tmdb_search_page`, half a TMDb page), music 12; at most 20 pages.
- **music_lookup.py**: Add Vinyl pre-fill from MusicBrainz (User-Agent with contact, 1 request/s per process, 6 h cache, `Busy` on 503) and Cover Art Archive covers.
- **media_lookup.py**: Add Movie or Show pre-fill: UPCitemdb (barcode) then TMDb (title), through the SSRF guard; `clean_title` strips tape noise, `split_season` a box set's season ("The Complete First Season" -> Season 1, "Season 1 & 2" -> Seasons 1 & 2, which fills Season and makes it TV). TMDb movies and TV are one `/search/multi` (`tmdb_search`, each result with its `kind`); a picked id travels with its kind (`/videos/lookup?tmdb_id=&kind=tv`, `tmdb_tv_details`: creators as Creator, runtime left empty). The cover fetcher's title search (`tmdb_movie`) finds shows too. Optional; manual entry is the main path.
- **have_online.py**: Do I have this?'s online candidates on "Not here" (ROADMAP 13b): the three sources at once in a small thread pool (a source past `DEADLINE` is left out, its thread fills the caches), `score_text` / `rank`, and each candidate's add links. A TMDb show is a "TV Show" (`video_kind` on the candidate) and its links carry `kind=tv`, so the add page starts on TV and looks it up as a show; each group carries its `heading`. Downloads nothing; thumbnails go through `coverSrc`.
- **backups.py**: site backups from Admin → Backups (`admin.backups_page`), added before shipping 14b. A backup is a folder in `BACKUP_DIR` (default `backups/` beside the database) named by time: `library.db` (SQLite online backup), `uploads/` (hard links to the covers and avatars, copies across filesystems; safe because upload files are never rewritten in place), `meta.json` (kind, who, migrations, counts). `create` / `list_backups` / `latest` / `restore` / `delete` / `folder` (validates names from URLs). `restore` refuses a backup with migrations this code doesn't know, brings an older one up to date on a scratch copy with `manage.apply_migration`, copies into the live DB with the online backup API (the route closes its own connection first) and links back missing upload files without deleting any. Made by hand only, kept until deleted; a restore can't be undone (no backup of the state it replaces, Phil's call 2026-11-12).
- **personal_backups.py**: each user's own library backups (Profile → Library backups, `user.personal_backup_*`; the Goodreads import takes one, kind `goodreads`, and refuses to import without it). A JSON snapshot of the books they added plus their rows in `USER_TABLES` (statuses, reviews, sessions, wishlist, tags, collections, goals, dismissed activities, bulk edits, Goodreads imports) and those tables' children, with hard links to their covers, in `BACKUP_DIR/users/<id>/<name>/`. Never the account, friendships, households, notifications or likes. `restore` (one transaction, the user's rows only): deletes their rows; deletes books added since unless `models.other_users_with_book_data`; puts back the backup's books (reinserted with their old ids if gone: every id here is AUTOINCREMENT and rows never change user, so old ids can't clash); leaves books given away since with the new owner; reinserts rows, skipping ones whose book is gone. A restore can't be undone (no backup of the state it replaces). Only columns both sides have are copied; a new required column refuses. `MAX_MANUAL` 10 per user, automatic ones pruned to 5.
- **book_matching.py**: finding an existing book to attach a user's data to (`BookIndex`, `own_book_for_wishlist`); `same_book` / `isbn_matches` give the Add page's duplicate check (`book_utils.find_duplicates`) the same title, subtitle and author rules (14c). Only the user's own books and their household's shelf are searched, never anyone else's. `books_in_common(conn, a, b)` (16.0, a friend's profile) counts books on both users' own shelves (`on_shelf`, books only, no wishlist entries, no household copies) by the same ISBN / title + author keys.
- **households.py**: household invites, joining, leaving and owner hand-over (see Access Model).
- **loans.py** (16.0d, `docs/LENDING-SPEC.md`): who has a physical copy. No Flask; callers commit; a refusal is `LoanError` (safe to show). `can_lend` (admin, or the item's owner or their household: `shelf_people`), `lendable` (on the shelf, not a wishlist entry; only Lend checks it, a loan doesn't follow shelf state afterwards), `borrower_choices` (the lender's circle, household first, active accounts), `open_loan`, `history` (all for the shelf's people, their own for a borrower), `lent_map` (the grids' badge, your household's shelf only), `borrowed_by`, `lent_out`, and the writes `lend` / `mark_returned` / `delete`, which notify the borrower (`loan`) on lending and the owner (`loan_owner`) when someone else lends or returns; never the person who acted.
- **email_utils.py**: verification tokens (random, stored in `email_verification_tokens`) and sending via Flask-Mail.
- **rate_limiting.py**: shared `limiter` instance.
- **errors.py**: 401 handler that redirects to login.

## Database Schema
Tables after all migrations:
- **Books and reading:** `books` (shared catalog, `added_by` = owner; a video's `video_kind` is `'tv'` or NULL = movie and `season` is TV's free text, migration 034, values in the `video_kinds` lookup table beside `media_types` and `statuses`), `collections` (per-user reading status), `read_data` (rating/comment), `reading_sessions`, `book_tags`, `user_collections` (custom shelves, one `media_type` each, names unique per section) + `collection_books`, `wishlist`.
- **Goals:** `reading_goals` (one per user and year, migration 029; `users.reading_goal` is the old single goal, unused).
- **Jobs:** `cover_jobs` (background cover and value fetching, `kind`, see `utils/cover_jobs.py`).
- **Photos, condition, value (16.0a, migrations 036 to 040):** `item_photos` (`book_id` CASCADE, `kind` REFERENCES `photo_kinds` (040, 041: back, spine, side, top, bottom, gallery; one of each but the gallery per item), `path`, `caption`, `position`); `condition_grades` (lookup per type, `sleeve_only` for a record sleeve's extras); on `books`: `condition`, `sleeve_condition`, `price_paid_cents`, `value_cents`, `value_source`, `value_note`, `value_checked_at`, `discogs_release_id`. Price and value are the owner's (and admins') only: the item page, the Collection value card on your own Stats (`stats.collection_value`) and your exports; condition shows to anyone who can see the item.
- **Placeholder faces (16.0c, migration 041):** `face_placeholders` (`medium`, `kind` in spine / side / top / bottom, `name`, `path`), `face_sets` (`medium`, `name`), `face_set_members` (`set_id`, `kind`, `placeholder_id`; both CASCADE), `item_faces` (`book_id`, `kind`, `placeholder_id`: an owner's pick; both CASCADE, so deleting a placeholder drops the picks). `find_orphaned_images` counts `face_placeholders.path` as in use.
- **Goodreads import:** `goodreads_staging` (an upload waiting for review: one row per CSV line, its choice), `goodreads_imports` (one per applied import, `edit_id` to its bulk journal entry), `goodreads_rows` (what each line did: `goodreads_id`, `book_id` SET NULL, `outcome`, `wrote`, `shelves`), migration 032. `goodreads_rows` is the provenance behind the From Goodreads grid filter (`grid_query.from_goodreads`), the book page note, the Book Id memory of the next import, and the kept Goodreads shelves.
- **Bulk edit:** `bulk_edits` (one per edit: action, params JSON, summary, `undone_at`) and `bulk_edit_items` (before/after JSON per item), migration 031. `collections.quiet = 1` marks a status set in bulk: the feed skips it, and setting the status by hand resets it to 0.
- **Users and social:** `users` (incl. `is_admin`, `is_active`, `avatar_url`, `bio`, `reading_goal`, `email_verified`), `friendships` (stored with `user_id_1 < user_id_2`), `friend_requests`, `notifications`, `activity_likes`, `dismissed_activities`, `email_verification_tokens`.
- **Loans (16.0d, migration 042):** `loans` (`book_id` CASCADE, `lent_by` and `borrower_id` SET NULL, `borrower_name` always filled, `lent_at`, `due_at`, `returned_at`, `note`); a partial unique index keeps one open loan per item.
- **Households:** `library_members` (one library per user; `library_id` groups members; exactly one `owner` per household), `household_invites` (pending invites).

## Image Handling
- Covers are uploaded or auto-fetched, resized to MAX_IMAGE_SIZE (500x1000), and stored under `static/uploads/` as `uploads/...` paths relative to `static/`. Avatars go in `static/uploads/avatars/`.
- Item photos (16.0a): `static/uploads/photos/<book_id>/<random>.jpg`, up to 2000 px on the long side, stripped of all metadata (`image_utils.save_photo`). Site backups copy them with the rest of `uploads/`; the personal data export puts your own in `photos/` with `photos.csv`. Personal library backups don't hold photos (a restored book that had been deleted comes back without them).
- Placeholder faces (16.0c): `static/uploads/faces/<random>.jpg`, saved like item photos (`image_utils.save_photo(..., folder=FACES_FOLDER)`); site backups copy them with the rest of `uploads/`.
- Fallback image (JS, when a cover fails to load): `static/no-cover.svg`. Templates show a themed "No Image Available" box instead.
- A stored cover or avatar whose file is gone is treated as none: templates test `{% if x.cover_image_url|upload_exists %}` (not the bare column), and `card_json` sends None. Use the filter in any new template that shows a cover.
- `app.py` sets `UPLOAD_FOLDER = static/uploads` (relative to the working dir), overriding the paths in config.py.

## Environment Variables
Read via python-dotenv from `.env`:
- **SECRET_KEY**: required in production. A warning is logged if it's still the `.env.example` placeholder.
- **GOOGLE_BOOKS_API_KEY**: Google Books lookups.
- **TMDB_API_KEY**: optional, film details for video lookups (v4 read access token preferred, or v3 key). Without it, UPCitemdb only.
- **DISCOGS_TOKEN**: optional, Discogs personal access token (discogs.com/settings/developers) for Add Album's search (`utils/discogs_lookup.py`). Without it, MusicBrainz only.
- **VALUE_CURRENCY**: the site's one currency for price paid and value (default `USD`); fetched prices in another are refused.
- **EBAY_CLIENT_ID / EBAY_CLIENT_SECRET**: optional, an eBay Production keyset for book and movie values (`utils/valuation.py`); the secret only ever goes in the token request's header. **EBAY_MARKETPLACE**: default `EBAY_US`. Discogs values use `DISCOGS_TOKEN` (seller settings must be filled in). Setup steps: docs/PHOTOS-VALUE-SPEC.md section 7.
- **MUSICBRAINZ_CONTACT**: contact in the MusicBrainz User-Agent (an email is best; default the GitHub URL).
- **FLASK_ENV**: `development` or `production`.
- **BACKUP_DIR**: where `utils/backups.py` keeps site backups (default `backups/` beside the database file). Never under `static/`. On prod, put it on the same filesystem as the uploads folder so covers are hard-linked rather than copied.
- **DATABASE_PATH**: SQLite file used by `utils/database.py` and `manage.py` (default `library.db` in the project directory).
- **ALLOW_REGISTRATION**: `False` closes self-registration once the first user exists (default `True`).
- **TRUSTED_PROXY_COUNT**: number of reverse proxies to trust for `X-Forwarded-*` (default 0 = off).
- **EMAIL_VERIFICATION_REQUIRED** and **MAIL_SERVER / MAIL_PORT / MAIL_USE_TLS / MAIL_USERNAME / MAIL_PASSWORD / MAIL_DEFAULT_SENDER**: email verification.
- **PORT**: dev server port.
- **CSP_REPORT_ONLY**: `true` sends the Content-Security-Policy as report-only (escape hatch; default enforced).

**Load order:** `app.py` calls `load_dotenv()` at import, before `config.py` is imported, and `utils/database.database_path()` reads `DATABASE_PATH` on every call. So every setting works from `.env` or the real environment (real env wins). A relative `DATABASE_PATH` is relative to the project directory, not the cwd. The app logs the DB path at startup and warns if the file doesn't exist.

## Authentication & Security
- The first registered user becomes admin. Admin routes use `@admin_required` from models.py.
- Passwords are hashed with the raw `bcrypt` module (not Flask-Bcrypt).
- Usernames must match `^[A-Za-z0-9_.-]{3,30}$`, can't be a page's name (`settings`, `export_data`, ...: anything that would make `/user/<name>` another route) and are unique ignoring case (`models.username_error`, unique index from migration 033); enforced on register, rename and admin create. `tests/test_username_collisions.py` derives the page names from the URL map, so a new route is covered.
- CSRF: Flask-WTF `CSRFProtect` is global, with `WTF_CSRF_TIME_LIMIT = None` (tokens last the session); a `CSRFError` flashes "That page was out of date" and goes back to the same-site referrer, or answers JSON to a fetch (`utils/errors.csrf_error`, 14c). Forms include `csrf_token()`; fetch calls send the `X-CSRFToken` header (both `X-CSRFToken` and `X-CSRF-Token` are accepted) using `getCSRFToken()` from `common.js`, which reads a hidden `csrf_token` input or the `<meta name="csrf-token">` that `base.html` puts on every page.
- Session and remember-me cookies are HttpOnly and SameSite=Lax. They are `Secure` only in production; remember-me lasts 30 days.
- `after_request` sets a **Content-Security-Policy** (`script-src 'self'`, `img-src 'self' data: blob:`, `connect-src 'self'`, `worker-src 'self'`; inline `style=` allowed), plus `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN` and `Referrer-Policy`. `CSP_REPORT_ONLY=true` makes it report-only.
- Rate limiting:
  - No global default (it caused 429s while browsing). Per-route `@limiter.limit()` on auth, profile updates, friend and household requests, and imports (`utils/rate_limiting.py`).
  - Storage is in memory, so each gunicorn worker counts separately (effective limit = limit x workers). Redis is the fix if that ever matters.
  - Behind a reverse proxy, set `TRUSTED_PROXY_COUNT` so limits use the real client IP.

- First-time setup: visit `/` and you'll be redirected to register the admin user (the first user is admin). Camera/barcode scanning needs HTTPS (`./generate-cert.sh`, `docs/HTTPS-SETUP.md`).
